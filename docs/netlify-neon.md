# Netlify Functions + Neon PostgreSQL

## Текущий статус

Код сайта использует Netlify Functions и Neon PostgreSQL. В этой рабочей среде нет доступа к аккаунтам Netlify и Neon, поэтому подключение базы, секреты и опубликованный сайт не подтверждены автоматически.

До публикации нужно выполнить действия из разделов ниже.

## 1. Создание базы Neon

1. Создайте проект в Neon на бесплатном тарифе.
2. Скопируйте pooled connection string для переменной `DATABASE_URL`.
3. Откройте SQL Editor в Neon.
4. Выполните файл `migrations/0002_neon_schema.sql`.
5. Убедитесь, что существуют таблицы `callback_requests`, `admin_rate_limits` и `callback_rate_limits`.

Миграция использует `CREATE TABLE IF NOT EXISTS` и не удаляет существующие таблицы или заявки. Если старые заявки находятся только в Cloudflare D1, их нужно отдельно экспортировать и импортировать в Neon до переключения production-трафика. Такой перенос здесь не заявляется выполненным, потому что доступ к D1 и Neon отсутствует.

## 2. Переменные Netlify

В настройках сайта Netlify добавьте серверные переменные:

- `DATABASE_URL` — pooled connection string Neon;
- `ADMIN_PASSWORD` — длинный уникальный пароль администратора;
- `SESSION_SECRET` — отдельная длинная случайная строка для подписи cookie;
- `TELEGRAM_BOT_TOKEN` — необязательно;
- `TELEGRAM_CHAT_ID` — необязательно.

Не добавляйте эти значения с префиксом `VITE_`. Они используются только серверными функциями и не должны попадать в браузерный JavaScript.

## 3. Подключение сайта

Для Netlify используйте:

- Build command: `npm run build`;
- Publish directory: `dist`;
- Functions directory: `netlify/functions`;
- Node version: 20 или новее.

Файл `netlify.toml` уже содержит эти настройки и маршруты `/api/*`.

## 4. Защищённая CRM

CRM доступна по адресу `/admin/requests`. Она не показывает заявки без действующей HttpOnly cookie-сессии. Сервер повторно проверяет сессию для списка, обновления CRM-полей и CSV-экспорта.

Первый вход выполняется паролем из `ADMIN_PASSWORD`. После входа администратор может:

- просматривать заявки, отсортированные от новых к старым;
- видеть имя, телефон, удобное время и согласие;
- указывать дату звонка, результат и комментарий;
- сохранять изменения в Neon;
- выгружать актуальные данные в CSV.

## 5. Проверка после публикации

1. Отправьте заявку с корректным телефоном и согласием.
2. Проверьте, что она появилась в Neon и в CRM.
3. Повторите запрос с тем же `Idempotency-Key` и убедитесь, что дубль не создан.
4. Попробуйте отправить форму без согласия — сервер должен вернуть ошибку.
5. Войдите в `/admin/requests`, заполните дату звонка, результат и комментарий.
6. Обновите страницу и убедитесь, что CRM-поля сохранились.
7. Скачайте CSV и проверьте BOM, девять колонок и актуальные значения.
8. Откройте CSV в Excel и проверьте строки с кавычками, переносами и значениями, начинающимися с `=`, `+`, `-` или `@`.
9. Откройте CSV без cookie — сервер должен вернуть `403`.
10. Временно отключите базу и убедитесь, что форма показывает ошибку, а не сообщение об успехе.

## 6. Уведомления

Если заданы обе Telegram-переменные, функция пытается отправить уведомление после сохранения. Ошибка Telegram не удаляет заявку: пользователь получает уведомление, что заявка сохранена, но уведомление владельцу не доставлено.

## 7. Безопасность и ограничения

- Пароль и строка подключения не попадают в клиентский код.
- SQL-запросы используют параметризованные шаблоны Neon.
- Публичная форма ограничена по размеру входных данных и частоте запросов.
- Вход администратора ограничен по частоте попыток.
- CSV защищён от формульной инъекции и экранирует кавычки, запятые и переводы строк.
- Текст согласия и реквизиты владельца персональных данных требуют отдельной юридической проверки перед публикацией.
- Бесплатные тарифы Netlify и Neon имеют свои лимиты по времени выполнения, запросам и простаиванию базы; контролируйте их в соответствующих панелях.
